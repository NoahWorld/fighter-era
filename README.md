# 战机时代 · FIGHTER ERA

公开仓库：[NoahWorld/fighter-era](https://github.com/NoahWorld/fighter-era)，默认分支为 `main`。

原生 Canvas 竖屏自动射击小游戏。采用肉鸽规则：击破敌机获得本局经验、升级战机，死亡结束远征，下次从第 1 关、Lv.1 重来。浏览器与微信小游戏共享一套引擎和画面，使用用户提供的本地透明图集；客户端无第三方运行依赖或远程图片、字体请求。独立账号后端采用 Node.js 22 + Fastify 5 + PostgreSQL 17，保存成长、通关与道具记录。

网站首页为 [字数统计工具](https://resetshi.work/)，文本仅在浏览器即时处理，不上传或保存。游戏体验入口为 [战机时代](https://resetshi.work/game)。微信云存档接入代码已加入，但默认 `apiBase` 为空，AppSecret 与微信 request 合法域名尚待配置；独立 API 地址为 `https://resetshi.work/api`。游戏当前默认仍仅本机保存；充值和广告只预留数据结构，没有启用。

## 浏览器试玩

域名状态（2026-10-04）：为备案准备，已暂停 `resetshi.work` 与 `www.resetshi.work` 的解析；上述域名入口待用户要求恢复解析后再启用。原服务保留，本地试玩仍可使用。

需要 Node.js 18 或更新版本。在项目目录运行：

```sh
npm start
```

打开 `http://127.0.0.1:4173/game` 体验游戏；`http://127.0.0.1:4173/` 为字数统计首页。通过 `PORT=4174 npm start` 可指定端口。服务默认监听本机 `127.0.0.1`，容器可配置 `HOST=0.0.0.0`；端口冲突会明确报错，不会自动换端口。仅提供首页和游戏所需公开静态资源，拒绝目录穿越请求。`/game` 与 `/game/` 均可打开，页面以站点根目录解析游戏素材。相同域名与协议下改路径不会改变本机存档来源。

点击「驾驶战机出击」后，先观看 3.2 秒飞行员登机、座舱合拢和起飞动画；进入战斗后按住画面任意位置相对拖动战机；手指不会让战机瞬移，松手仍持续开火。点击右侧「救援」「轰炸弹」使用技能，每局免费各一次，过关不补充。电脑也可使用方向键或 WASD，R 呼叫救援、B 使用轰炸弹、P / Escape 暂停与继续。使用 Tab 可访问画面上的可用按钮，Enter / 空格激活；焦点有可见描边。

浏览器音效默认关闭，点击「音效 · 关」开启。声音通过用户操作启动 Web Audio；不支持音频时会显示诊断提示。切换窗口或页面隐藏会暂停，回到游戏后需手动继续。

正常帧间隔在 0.25 秒以内时，完整保留实际经过的时间，由引擎细分计算，避免低帧率导致游戏变慢。战斗、登机或弹射状态下单帧停顿超过 0.25 秒时会明确提示、暂停战斗并重置计时，需手动继续。菜单、升级选择和结果等非战斗状态没有战斗推进，较长的调度间隔只重置计时，不作为故障提示；浏览器和微信入口遵循同一规则。

## 内容

- 每次出击包含 100 关，分为 10 个星域，每星域 10 关：星港边境、碎星航道、赤焰星云、环星禁区、幽蓝星河、暗影星带、恒星熔炉、极光星域、虚空裂隙、核心决战。
- 星空、远景行星与蓝银战机画面；十个星域分别有航道、星环、陨石带、轨道遗迹、网格星港、双星、星云裂隙、螺旋星系、冰晶和恒星风；每关进一步切换布局、角度、密度和天体位置。星点与天体分层向下滚动、离屏循环，体现战机前进。背景复用固定数量的图形，不增加大图资源；暂停时停止滚动。敌人包括红色敌机、战舰（`warship`）和敌对行星（`planet`）。
- 自动射击、敌机编队、弹幕、首领、掉落道具与战机受伤反馈。新增 10 款红色战机、10 款红色战舰；BOSS 交替使用战机与战舰形态，含三种攻击模式。左侧生命条保持固定高度，用比例与数值表达成长后的生命值。
- 呼叫救援后，两架友机飞入编队并自动射击，8 秒后撤离（包含进出场）；暂停和切后台会冻结援军计时。过关或己方被击败后援军结束行动；每局只免费一次，过关与续关不补充。
- 轰炸弹立即击败画面内敌人，包括 BOSS，并清除敌方弹幕；我方战机、援军、已有增益、拾取道具及击杀掉落保留。正常计分和获得本局经验。全屏冲击波短暂显示，结算时正常消退；每局只免费一枚，过关与续关不补充。
- 每次开局和重新出击都有飞行员跑向战机、跳入座舱、起飞的动画。装甲耗尽后先播放 2.6 秒飞行员弹射逃生，再出现「我方战机已被击败」结算。动画期间战斗冻结，暂停或切后台后可从原处继续。动画用 Canvas 轻量绘制，复用现有战机图集。
- BOSS 登场时屏幕边缘柔和闪红三次，持续 2.4 秒，并显示「BOSS 出现」；击败后明确显示「BOSS 已击败」，最后一关显示「最终 BOSS 已击败」。
- 过关后选择扩散火力、极速机炮或装甲补给，再进入下一关。极速机炮的基础射击间隔最低为 0.07 秒，达到上限后增加 0.4 伤害，选择说明随之变化；实际开火间隔还会除以等级和关卡的成长倍率。后期敌人移动、弹速、波次间隔与 BOSS 射击间隔有边界，关卡数量不会令射速无限增长。
- 击破敌机获得本局经验，等级提升会增强火力与生命上限；死亡或新开局后全部归零。
- 我方战机 Lv.1–20 各有不同型号与外形，本局成长至 20 级后显示 MAX；关卡继续推进时仍提升火力。敌方战机与战舰各有 20 个等级，每 5 关递增一档，整体以红色为主。
- 菜单「战机图鉴 · 20 级形态」可查看我方战机、敌机与战舰的 20 级外形、挂载槽位及可用武器。图鉴只供介绍，没有选机或装备按钮，新出击仍从 Lv.1 基础机炮开始。
- 机炮始终保留；光柱、追踪弹和爆炸弹拾取后加入武器库，重复拾取强化该路武器（最高 5 级）。Lv.1/2/6/10 分别开放 1/2/3/4 个同时开火的槽位，按机炮、光柱、追踪弹、爆炸弹顺序挂载，其余储备至扩槽。等级与关卡共同提高伤害及射速，四路武器分别计时。
- 胜利、失败与重新开始流程。每局分数和局内武器升级独立计算，本局成长与历史最高分分开保存。
- 菜单有存活存档时显示「继续闯关」。中断后从当前关卡开头重新挑战，经验与装甲回到该关起点；拾取后的武器类型与武器等级即时保存，已消耗的免费技能次数不恢复。在升级选择界面退出后，再次继续仍回到选择界面。

游戏仍在客户端模拟战斗；后端负责账号与记录，不是多人联机或完整战斗服务器。目前没有排行榜、在线联机、已启用的广告或支付。本局成长只影响本次远征。死亡后可打开原地复活面板；广告与充值均显示待开通，当前不能复活。

## 美术素材

六张 PNG 图集由用户提供并授权用于本游戏，原四张保存在 `assets/player.png`、`assets/enemies.png`、`assets/warships.png`、`assets/projectiles.png`，新增两张位于 `assets/expansion/enemy-variants.png`、`assets/expansion/fleet.png`。图像仅重新压缩 PNG 数据，解码后的 RGBA 与原图一致；六图合计约 6.76 MiB，新增两图约 3.02 MiB。素材在实际显示尺寸下足够清晰，未进行 AI 重绘或放大。用户的分类总览图用作外观参考，未把其中较小的带字图样直接替换游戏精灵。

我方战机、敌机与战舰各 20 个型号已经接入；现有图集提供基础外观，后十级我方和部分后期敌方加入不同翼面、炮舱和发动机轮廓。目录与挂载说明统一在 `src/aircraft.js`，战斗和机库复用同一型号。拾取道具叠加普通弹、穿透光柱、追踪弹和范围爆炸弹，各路独立强化，武器等级另表示本局机炮扩散强化。敌机、战舰、行星和 BOSS 也搭配这些攻击，敌方光柱先给出锁定预警，整体仍以红色为主。`src/assets.js` 维护尺寸、精灵源矩形和加载流程，渲染保留透明背景与宽高比；邻近精灵的包围盒重叠时，用同一比例绘制互不重叠的区域，避免相邻机头或尾焰串入。部分预留弹药图样尚未启用。六图加载完成前不可开局；素材缺失、尺寸错误或解码超过 15 秒会明确显示路径与错误并停止。

微信端新增图集放入 `fleet-assets` 资源分包，保留 `assets/expansion/game.js` 必需入口。启动先调用 `wx.loadSubpackage` 并显示下载进度，成功后才解码六图；失败、无效 API 或 30 秒超时均明确停止，不能静默省略新增舰队。主包与扩展包分别检查资源预算；浏览器从同一本地目录直接读取图片。

## 肉鸽与存档规则

- 新出击始终从第 1 关、Lv.1、零经验和基础战机开始；死亡立即清空本局经验、强化与续关，弹射动画只展示刚结束的战机；最高分在致命伤时立即保存。最终胜利也结束本局成长。
- 暂停、回机库或关闭时仍存活，可继续该关起点；恢复起点经验、装甲、分数和随机状态，保留该关已消耗的免费救援与轰炸次数。关中拾取即时更新武器类型、各路等级与机炮扩散强化，不更新边界经验、生命或分数。旧三/四字段武器存档显式归一化为机炮和原特殊武器各 1 级，新字段严格校验。升级选择中退出可回到选择界面，不重复奖励 BOSS。
- 本局记录使用一个原子键 `fighter-era.run.v2`：`{version:2,profile:{version:2,totalXp},checkpoint}`。续关版本为 2，含边界 `totalXp`，没有存活续关时经验必须为零。旧永久成长与续关键保留但不导入新规则，并显示更新提示。
- 最高分仍使用 `neon-wing.best-score`，历史通关记录也保留；这些成绩不会增强下一局。
- 损坏或失败的存储会明确提示并停止覆盖原记录；临时游玩时无法保证关闭后保留。浏览器试玩只在同一浏览器、同一地址保存，清除浏览器数据或换设备不会同步。
- **广告与充值复活待接入**。当前不允许死亡后免费续关。原地复活和道具获取面板的广告、充值按钮禁用并标注待开通；后续须由真实平台与服务端确认资格后开放。

## 微信云存档与道具

配置后，微信入口使用 `wx.login()` 获取 code，由后端向微信兑换身份，再通过自有令牌读取账号。当前记录账号标识、本局经验、最高分、最高通关关卡、每关通关次数、续关点、额外炸弹及支援库存；没有获取头像、昵称或做好友排行。AppSecret 只保留在服务器，客户端不能指定自己属于哪个用户。

微信端每次经验变化、续关点变化及结算先同步写入本机待发送队列，再在关卡边界、切后台或每 10 秒发送。网络结果未知时保留原请求编号重试，服务端用事务和唯一索引避免重复计通关或扣道具。存档版本冲突、队列保存失败和网络重试会明确提示；队列满时不会静默删除旧记录。每次新开或继续挑战使用新的对局编号，终局记录不会被后续一局覆盖。

新微信账号可一次性导入从未绑定过账号的新版存活对局、最高分和续关点。客户端先检查账号上下文，再发送已有待同步记录；只有本机上下文为空、队列未绑定账号且服务端允许首次迁移时才导入。已经绑定账号的本机镜像不再导入，切换账号或同账号重新登录也一样；已有云档不能被本机档直接覆盖，本机经验与已有云账号不自动相加。

读取云档成功后，先同步写入本机账号绑定，再更新本机镜像；上下文损坏、同步失败或绑定保存失败时停止入口并保留原记录。已启用云配置但登录失败时也会明确提示错误并停止开局，避免新进度后来被旧云档覆盖；空 `apiBase` 才使用默认本机模式。清理微信存储会删除尚未同步的队列，因此待同步状态不等于云端已保存。

每局免费轰炸和救援各一次，过关与续关不补充，额外库存单独保存。用尽后打开获取面板，战斗暂停；当前广告和充值入口均不可使用。免费次数用完后，只有服务端确认扣除额外库存，游戏才应用对应技能；扣除结果未知时保留记录，避免重复扣除。普通存档接口不能修改库存。数据库已有库存流水、支付订单和广告奖励记录表，内部发放方法按来源编号去重；**没有启用充值、广告播放、付款回调或广告发奖接口**，也没有可用的充值商品和广告位。

启用真实微信登录需要：

1. 将小游戏 AppSecret 配置在服务器 `deploy/.env`，不提交到公开仓库。
2. 在微信平台登记 HTTPS API 的 request 合法域名；服务器已配置 `resetshi.work` HTTPS 网关。
3. 将 `src/cloud-config.js` 中公开的 `apiBase` 设置为 `https://resetshi.work/api`，再进行开发者工具与真机验证。

配置保持空时，微信显示「云存档待配置 · 当前仅本机保存」，不调用登录接口。后端未配置 AppSecret 时返回 `503 WECHAT_NOT_CONFIGURED`，不会建立假账号。API 契约见 [后端说明](backend/README.md)。

## 后端与服务器

后端独立安装与运行，要求 Node.js 22，客户端浏览器试玩仍只需 Node.js 18 或更新版本：

```sh
npm --prefix backend ci
npm --prefix backend run check
npm --prefix backend test
```

运行服务还需要 PostgreSQL 数据库与私有配置，步骤见 [后端说明](backend/README.md)。默认本地 API 为 `127.0.0.1:4317`；生产 Compose 使用 Node.js 22 与 PostgreSQL 17，专用目录为 `/opt/fighter-era`，API 仅向宿主机发布 `127.0.0.1:8088`，数据库不发布公网端口。独立 Caddy 网关使用 TCP 443，提供游戏和 `/api/*` 后端接口，证书自动续期，不占用原应用的 80 端口。

**既有 `/opt/learning-workbench` 及其服务、数据库、配置不得修改。** 战机时代使用独立 Compose 项目、卷与数据库凭据。部署、健康检查、更新与备份操作见 [部署说明](deploy/README.md)。独立浏览器试玩目录为 `/opt/fighter-era/playtest`，默认公开端口 8080，云安全组需放行 TCP 8080；浏览器版本当前仅本机存档。备份写入 `/opt/fighter-era/backups`，不进入 Git；备份文件和真正验证过的恢复要分开记录。

## 微信开发者工具

1. 使用微信开发者工具导入本项目，项目类型选择「小游戏」。
2. 在开发者工具中选择当前账号可用的测试身份；正式发布前配置自己的真实小游戏 AppID。`project.config.json` 保留工具选择的身份，不要用占位值覆盖已配置的测试号或正式 AppID，测试身份不能代替正式发布身份。
3. 入口是根目录 `game.js`，竖屏设置在 `game.json`。不需要先运行浏览器服务器。
4. 在开发者工具及真机上检查触摸、屏幕比例、安全区域、前后台暂停和帧率。

微信入口使用 `wx.createCanvas`、`wx.getWindowInfo`、触摸事件、本地存储和生命周期 API。按实际屏幕尺寸等比缩放并保留黑边；输入通过同一变换映射到 405 × 720 的逻辑坐标。只跟踪第一根有效手指，按钮优先，点击按钮后继续按住不会误拖战机。

**微信版当前没有音频。此前永久成长版本已在微信开发者工具中完成编译、菜单渲染、点击出击、实战自动射击、战舰与 3 级战机外观变化检查；当时重新编译后菜单保留经验。当前肉鸽版本尚未重新完成开发者工具检查，真机兼容和平台发布审核也尚未验证。** 已在模拟器实测单指相对拖动；多指、边缘触控仍需专项核验，开发者工具运行不能代替真机验证。当前运行环境如果缺少所需 API，将明确显示错误并停止，不伪装成功。

## 验证与排错

武器叠加与 20 级图鉴版本于 2026-10-04 通过客户端 185 项测试、语法检查及服务器后端 48 项测试（23 项单元、25 项真实 PostgreSQL），均 0 失败、0 跳过。测试覆盖四路共存、强化、旧存档迁移、死亡清零、只读图鉴和微信触摸锁定；全部 100 关运行数量边界检查。实际武器伤害模拟中，第 80/90/99/100 关的满级机型、四路 5 级武器击败 BOSS 约需 5.6–6.1 秒；该模拟持续跟随 BOSS，不代表人工通关或真机帧率。

## 文件

- `src/engine.js`：与平台无关的状态、碰撞、敌人及关卡逻辑。
- `src/aircraft.js`：双方 20 级机型目录、外形与挂载能力，供战斗和只读图鉴共用。
- `src/renderer.js`：405 × 720 逻辑尺寸下的 Canvas 绘制与按钮布局。
- `src/assets.js` / `assets/`：用户提供的透明 PNG 图集、源矩形与严格加载流程。
- `src/browser.js`：浏览器输入、像素比例、音频、存储、暂停和可达性按钮。
- `index.html`：单文件字数统计首页。
- `game.html` / `style.css`：`/game` 游戏入口、桌面飞行面板与手机适配。
- `game.js`：微信输入、屏幕映射、存储与生命周期。
- `src/cloud-save.js` / `src/wechat-cloud.js`：持久待发送队列、微信账号同步与额外道具使用。
- `src/cloud-config.js`：公开的 HTTPS API 地址，默认为空；不能放密钥。
- `backend/`：Node.js 22 + Fastify 5 API、数据库迁移与后端测试。
- `deploy/`：独立 Docker Compose 配置、数据库初始化、备份脚本与计时器。
- `server.js`：采用公开资源白名单的静态试玩服务器，默认监听本机。
- `tests/`：无依赖自动化测试。
